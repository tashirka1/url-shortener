## ДОБАВЛЕННЫЕ Требования

### Требование: API авторизуется через Bearer-токен
Система ДОЛЖНА авторизовывать API-запросы через заголовок `Authorization: Bearer <token>`. Неавторизованные запросы ДОЛЖНЫ получать ответ 401.

#### Сценарий: Валидный токен
- **КОГДА** запрос содержит валидный заголовок `Authorization: Bearer <token>`
- **ТОГДА** запрос авторизуется от имени пользователя-владельца токена и обновляется `last_used_at` токена

#### Сценарий: Отсутствует токен
- **КОГДА** запрос не содержит заголовок `Authorization`
- **ТОГДА** система возвращает `401 Unauthorized` с JSON-телом `{"error": "missing authorization header"}`

#### Сценарий: Невалидный токен
- **КОГДА** запрос содержит заголовок `Authorization` с токеном, чей хеш не соответствует ни одному активному (неотозванному) токену
- **ТОГДА** система возвращает `401 Unauthorized` с JSON-телом `{"error": "invalid token"}`

#### Сценарий: Отозванный токен
- **КОГДА** запрос содержит отозванный токен
- **ТОГДА** система возвращает `401 Unauthorized` с JSON-телом `{"error": "token revoked"}`

### Требование: POST /api/v1/link — Создать короткую ссылку
Система ДОЛЖНА позволять создавать короткие ссылки через API.

#### Сценарий: Успешное создание
- **КОГДА** пользователь отправляет `POST /api/v1/link` с JSON-телом `{"url": "https://example.com"}`
- **ТОГДА** система создаёт короткую ссылку и возвращает `201 Created` с JSON `{"code": "abc1234", "url": "https://example.com", "short_url": "http://localhost:8000/abc1234"}`

#### Сценарий: Отсутствует поле URL
- **КОГДА** пользователь отправляет `POST /api/v1/link` без поля `url` или с пустым URL
- **ТОГДА** система возвращает `400 Bad Request` с JSON-телом `{"error": "url is required"}`

#### Сценарий: Невалидный URL
- **КОГДА** пользователь отправляет `POST /api/v1/link` с некорректным URL
- **ТОГДА** система возвращает `400 Bad Request` с JSON-телом `{"error": "invalid url"}`

#### Сценарий: Дубликат URL
- **КОГДА** пользователь отправляет `POST /api/v1/link` с URL, который уже существует для этого пользователя
- **ТОГДА** система возвращает `409 Conflict` с JSON-телом `{"error": "link already exists", "code": "abc1234"}`

### Требование: GET /api/v1/link — Список ссылок
Система ДОЛЖНА возвращать список коротких ссылок пользователя через API с курсорной пагинацией.

#### Сценарий: Успешный список
- **КОГДА** пользователь отправляет `GET /api/v1/link`
- **ТОГДА** система возвращает `200 OK` с JSON `{"links": [...], "next_cursor": 42}`

#### Сценарий: Пагинация
- **КОГДА** пользователь отправляет `GET /api/v1/link?cursor=42`
- **ТОГДА** система возвращает следующую страницу ссылок начиная с курсора `42`, `next_cursor` содержит ID последней возвращённой ссылки

### Требование: DELETE /api/v1/link/:code — Удалить ссылку
Система ДОЛЖНА позволять удалять короткие ссылки через API.

#### Сценарий: Успешное удаление
- **КОГДА** пользователь отправляет `DELETE /api/v1/link/abc1234`
- **ТОГДА** система удаляет ссылку и возвращает `200 OK` с JSON `{"deleted": "abc1234"}`

#### Сценарий: Ссылка не найдена
- **КОГДА** пользователь отправляет `DELETE /api/v1/link/nonexistent`
- **ТОГДА** система возвращает `404 Not Found` с JSON-телом `{"error": "link not found"}`

### Требование: GET /api/v1/link/:code/stats — Статистика кликов
Система ДОЛЖНА возвращать статистику кликов по ссылке через API.

#### Сценарий: Успешная статистика
- **КОГДА** пользователь отправляет `GET /api/v1/link/abc1234/stats`
- **ТОГДА** система возвращает `200 OK` с JSON `{"code": "abc1234", "total_clicks": 42, "daily_clicks": [{"date": "2026-07-01", "clicks": 5}, ...], "top_referrers": [{"referrer": "https://t.co", "clicks": 10}, ...]}`

#### Сценарий: Ссылка не найдена
- **КОГДА** пользователь отправляет `GET /api/v1/link/nonexistent/stats`
- **ТОГДА** система возвращает `404 Not Found` с JSON-телом `{"error": "link not found"}`
