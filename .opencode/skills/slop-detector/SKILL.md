# Skill: slop-detector

Проверяет Go-проект на признаки «нейрослоповости» — стилистических паттернов, характерных для AI-сгенерированного кода: комментарный шум, неестественные имена, архитектурные аномалии, монотонный ритм.

### Input

По умолчанию — все `.go`, `.css`, `.js` и `.templ` файлы в проекте.
Опционально: можно указать путь `--path=internal/link/` для проверки конкретной директории.

### Процедура (шаг за шагом)

**Шаг 0. Определи scope**
Если указан `--path` — работай только внутри него. Если нет — проверяй корень проекта (рекурсивно, исключая `vendor/`).

**Шаг 1. Сбор метрик (bash)**
Для каждого пункта чек-листа выполни сбор данных через bash/grep/rg. Сохраняй результаты для анализа.

**Шаг 2. Анализ по чек-листу (каждый пункт)**
Пройди по каждому пункту. Если порог превышен — зафиксируй проблему с severity и указанием файла:строки.

**Шаг 3. Вывод отчёта**

### Чек-лист проверок

#### 1. Комментарный шум (Comment Noise)

**1.1 Общий объём комментариев**
- `find . -name '*.go' | xargs wc -l` — общий LOC
- `rg '^\s*//' --type go | wc -l` — строки-комментарии (line comments)
- Если процент коммент-строк > 30% от общего LOC — Medium

**1.2 Очевидные комментарии**
- Поиск паттернов: `// increment`, `// decrement`, `// return`, `// check if`, `// set the`, `// get the`, `// do nothing`, `// this function`
- `rg '(// (increment|decrement|return|check if|set the|get the|this function))' --type go` 
- Каждое совпадение — Low, файл:строка

**1.3 Doc-комментарии на unexported функциях**
- Идиоматичный Go: doc-комментарии (`// Foo`) — только для экспортированных функций
- Найти `^(// [a-z]|[ \t]+// [a-z])` рядом с `func [a-z]` — признак AI-стиля
- `rg '(// [a-z].*\nfunc [a-z])' --type go --multiline` 
- Каждое совпадение — Low

**1.4 Избыточные inline-комментарии к тривиальным операциям**
- Поиск `//.*(err|nil|true|false|ok|error|result)` на строках с тривиальными присваиваниями
- `rg '(err|result|ok).*(//.*(err|result|ok|nil|return))' --type go`
- Medium, если >5 совпадений на 1000 LOC

#### 2. Именование (Naming)

**2.1 Аномально длинные идентификаторы**
- Поиск имён длиннее 30 символов: `rg -P '\b[a-zA-Z_][a-zA-Z0-9_]{30,}\b' --type go`
- Каждое совпадение — Medium, файл:строка
- Игнорировать импорты (путь пакета) и URL в тестах

**2.2 Абстрактные универсальные имена**
- Поиск `data`, `item`, `result`, `value`, `input`, `output`, `info`, `helper`, `util`, `manager` как имён параметров/переменных
- `rg '(func.* (data|item|result|value|input|output|info|helper|util|manager) | (data|item|result|value|input|output|info) :=)' --type go`
- Low — каждое совпадение, Medium — если >10 на файл

**2.3 Венгерская нотация / не-Go нейминг**
- Поиск snake_case в Go-функциях (не тесты): `rg '[a-z]+_[a-z]+[a-z]+\b' --type go`
- Low — каждое совпадение в теле функции (не в импортах, не в тестах)
- Игнорировать: имена в тестах (`TestXxx`), константы, файлы тестов

**2.4 Шаблонные AI-имена**
- Поиск паттернов: `myVariable`, `exampleData`, `sampleText`, `dummyValue`, `testFunc`, `tempVar`
- `rg '(myVariable|exampleData|sampleText|dummyValue|testFunc|tempVar|placeholderValue)' --type go`
- Low — каждое совпадение

#### 3. Типы и сигнатуры (Types & Signatures)

**3.1 Использование `any` / `interface{}`**
- `rg '\bany\b' --type go` и `rg '\binterface\{\}\b' --type go`
- Исключения: поле у `Error` в JSON-ответах, signal.NotifyContext, Printf/printf-like
- Medium — если >5 non-trivial использований
- High — если `any` используется в сигнатурах своих функций (не в вызовах сторонних API)

**3.2 Использование `reflect`**
- `rg '"reflect"' --type go`
- Critical — каждое использование (запрещено AGENTS.md)

**3.3 Использование `panic` / `init()`**
- `rg '\bpanic\b' --type go`, `rg '^func init\b' --type go`
- Critical — каждое использование (запрещено AGENTS.md)

**3.4 Функции с 3+ возвращаемыми значениями**
- `rg '^func.*\(.*,.*,.* .*\)' --type go` (грубая проверка: 3+ параметров в возврате)
- Medium — каждая функция с 3+ возвращаемыми значениями (кроме конструкторов с ошибкой)

**3.5 Функции с 6+ параметрами**
- `rg '^func \([^)]+\) [^(]+\([^)]+,[^)]+,[^)]+,[^)]+,[^)]+,' --type go` 
- Medium — каждая такая функция

#### 4. Архитектурные аномалии (Architecture)

**4.1 Монотонный ритм (однообразие длины функций)**
- Собрать длины всех функций в каждом файле: bash + awk
- Если в файле 5+ функций и разница между min и max длиной ≤ 8 строк — Medium
- Признак AI: все функции получаются примерно одинакового размера

**4.2 Глубокие вложенности (>4 уровня)**
- `rg '^\s{20,}' --type go` (4 уровня = 20 пробелов с tab-stops 4)
- Medium — каждое совпадение (нарушение AGENTS.md, макс 3 уровня)

**4.3 Одинаковый паттерн обработки ошибок во всех функциях**
- Если в файле 8+ функций и у всех идол 1:1 `if err != nil { return err }` без `fmt.Errorf` — Low
- Признак AI: не оборачивает ошибки контекстом
- `rg '(if err != nil \{\s*return err\s*\})' --type go --multiline`

**4.4 Лишние интерфейсы с одной реализацией**
- Найти интерфейсы, у которых ровно 1 реализация (struct) в том же пакете
- grep: найти все `type Foo interface` и проверить кол-во реализаций
- Medium — интерфейс, который не импортируется из других пакетов и имеет 1 реализацию
- Low — интерфейс, который импортируется из 1 пакета и имеет 1 реализацию

#### 5. «Галлюцинации» и устаревшие API (Hallucinations)

**5.1 Устаревшие пакеты**
- Поиск импортов: `"io/ioutil"`, `"golang.org/x/net/context"`, `"errors.Wrap"`, `"github.com/pkg/errors"`
- High — каждое использование deprecated-пакета

**5.2 Несуществующие распространённые методы**
- Поиск: `.ToLower()`, `.ToUpper()`, `.hasOwnProperty()` (JS в Go), `.toString()` (Java в Go)
- В Go: `strings.ToLower`, `strings.ToUpper`
- High — каждое совпадение

**5.3 Неправильный конструктор sqlite**
- Поиск: `sql.Open("sqlite"` или `sql.Open("sqlite3", ...)` без `_ "github.com/mattn/go-sqlite3"`
- High — если driver imported but wrong open string, или open string without driver

#### 6. Избыточная защита (Defensive Overkill)

**6.1 `len(x) > 0` перед `for range`**
- Поиск паттерна: `if len\(.*\) > 0\s*\{` на строке, предшествующей `for range`
- Low — каждое совпадение (range над слайсом/мапом безопасен, проверка избыточна)

**6.2 Redundant nil check before range**
- Поиск: `if .* != nil\s*\{` идущий перед `for range .*\{`
- Low — каждое совпадение (range над nil-map/slice безопасен)

**6.3 Double error check**
- Два `if err != nil` подряд в одной функции без изменения `err` между ними
- Low — каждое совпадение

### Формат вывода

```
### slop-detector report

**🐛 Critical**: `internal/foo/bar.go:42` — Использование `reflect` (нарушение AGENTS.md)
**🐛 High**: `internal/foo/service.go` — Использование deprecated-пакета `"io/ioutil"`
**⚠️ Medium**: `internal/foo/handler.go` — Комментарный шум: 42% строк — комментарии (порог 30%)
**⚠️ Medium**: `internal/foo/api.go:15` — Идентификатор `processedDataListResult` (35 символов) выглядит AI-генерированным
**ℹ️ Low**: `internal/foo/util.go:33` — Doc-коммент на unexported функции `parseInput`
**ℹ️ Low**: `internal/foo/handler.go:88` — Избыточная проверка `len(x) > 0` перед `for range`

### Не применимо / нет проблем

Категории, где пороги не превышены, или проверка не дала результатов.
```

### Guardrails

- **Не выдумывай проблемы** — если результат проверки неоднозначен, пропусти.
- **Учитывай контекст проекта** — `any` в JSON-хендлере Echo — нормально. `any` в бизнес-логике — подозрительно.
- **Severity должен быть реалистичным** — `Critical` только за `panic`, `reflect`, `init()`.
- **Не проверяй `vendor/`** — только код проекта.
- **Избегай false positives** — если сомневаешься, лучше пропусти, чем ложное срабатывание.
- **Никогда не исправляй код** — это скилл ревью. Только находи проблемы, указывай файл:строка и объясняй причину. Изменения кода — только если пользователь явно прикажет после ревью.

### Справочник

**Пороги срабатывания:**
- Комментарный шум: >30% коммент-строк от общего LOC = Medium
- Длина идентификатора: >30 символов = Medium
- `any`/`interface{}`: >5 нетривиальных использований = Medium
- Абстрактные имена: >10 на файл = Medium
- Функции с 3+ возвратами: каждое совпадение = Medium
- Монотонный ритм: разница min-max ≤ 8 строк при 5+ функциях = Medium
- Очевидные комментарии: каждое совпадение = Low

**Severity:**
- `Critical` — нарушает жёсткие запреты AGENTS.md (panic, reflect, init)
- `High` — серьёзная архитектурная или安全问题 (deprecated API, галлюцинации)
- `Medium` — вероятный AI-паттерн (комментарный шум, длинные имена, вложенности)
- `Low` — подозрительно, но может быть случайностью (snake_case, redundant guard)
