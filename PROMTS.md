# Промты для сценариев работы

## 1. Создание новой функции

```
Действуй строго по правилам из файла @AGENTS.md в корне проекта.

Спроектируй и реализуй функцию <ИМЯ_ФУНКЦИИ>.

Use case:
- Основной сценарий: <опиши успешный поток>
- Исключительные случаи:
  - <случай 1>
  - <случай 2>

Требования:
- Слой model — сущности (структуры)
- Слой storage — database/sql запросы к sqlite3, context.Context первым аргументом
- Слой service — бизнес-логика, use case
- Слой handler — HTTP handler, читает request, вызывает service, рендерит templ компонент
- templ для HTML шаблонов, htmx для динамики
- Ошибки пробрасываются как (result, error) — не логировать в storage/service, логировать в handler
- Нет глобальных переменных, нет any/interface{}, нет init(), нет panic
- Табличные тесты для storage и service (_test.go рядом)
```

## 4. Реализация use case
Прочитай правила разработки в AGENTS.md.
Реализуй Use Case «Создание проекта»:
Main course:
1. Пользователь заполняет форму (Название, Описание).
2. Нажимает «Создать».Система проверяет данные, сохраняет проект в БД, привязывает к текущему пользователю.
3. Система возвращает элемент новой строки для добавления в общий список проектов на лету.

Exceptional course:
3a. Название проекта пустое или длиннее 50 символов: система прерывает процесс и возвращает ошибку валидации под полем ввода.
3b. Проект с таким названием уже существует у этого пользователя: система прерывает процесс и возвращает ошибку «Название занято».Начнем с Шага 1 (Model + Storage). Напиши код для них.
